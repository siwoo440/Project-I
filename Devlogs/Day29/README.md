## 1. 원정 실패와 부활

던전에서 전원 사망하면 `PersistentMapLoader`가 실패 귀환을 시작한다.

```text
사망 감지 → 3초 대기 → 소지품 정리 → 사무소로 강제 이동 → 마차 적재칸에서 부활
```

상실·유지 규칙:

| 구분 | 처리 |
| --- | --- |
| 손에 든 물건 · 인벤토리 | 상실 |
| 마차 적재칸에 실은 물건 | 상실 |
| 던전 바닥에 떨어뜨린 물건 | 상실 |
| 마차 공동 보관함 | **유지** |
| 자금 | 변동 없음 |

사망 시 `PlayerDeathController`가 이미 인벤토리를 바닥에 떨어뜨리기 때문에, 정리 대상에 던전 씬에 남은 물건과 플레이어 아래 물건까지 포함시켰다. 검증에서 21개 / 가치 24,591이 정리되는 것을 확인했다.

부활은 `PlayerHealth.ReviveFull()` + `PlayerDeathController.Revive()`로 처리한다. 래그돌을 숨기고 카메라 로컬 자세를 복원한 뒤 조작을 되살린다. 실패해도 그날 원정은 종료 처리라 같은 날 재출발은 거부되고, 일차 마감을 거쳐 다음 날 정상 출발한다.

## 2. 여러 칸 방 · 보스방 · 비밀방

`RoomShape`(Single / Wide / Hall / Ell / Boss)를 도입해 방 하나가 여러 격자 칸을 차지할 수 있게 했다. 방끼리 칸이 겹치지 않고, 한 방의 칸들은 반드시 이어져 있다.

```text
시드 300개 검사
  보스방   300/300 생성 · 전부 최심층 9칸 · 입구 1개
  비밀방   300개 · 전부 금 간 벽으로만 연결
  다칸 방  15,907개 중 4,124개
           Single 11,783 / Wide 2,107 / Ell 1,140 / Hall 577 / Boss 300
```

- 보스방: 최심층에 3x3으로 배치하고 입구를 1개로 제한. 순환로·막다른 방 보정·서브문 대상에서 제외.
- 비밀방: 입구가 금 간 벽 하나뿐. `BreakableWall`은 `CombatFaction.Neutral`이라 플레이어가 부술 수 있고, 부서지면 충돌체가 꺼지며 바닥으로 가라앉는다.

## 3. 마차 천막과 이동 중 자유 이동

`WagonTravelCover`가 적재칸 크기를 읽어 5면(좌·우·앞·뒤·지붕) 패널을 만든다. 출발하면 패널이 펴져 바깥이 보이지 않고, 도착하면 말려 올라간다.

이동 연출 중에는 시점 고정을 풀었다. 다만 사무소 입구 구조물에 플레이어 캡슐이 걸려 마차 뒤로 밀리는 문제가 있어서, 진입 연출 동안에는 **적재칸 기준 탑승 이동**으로 처리한다.

```text
PlayerMovement / CharacterController 를 잠시 끔
마차 기준 로컬 좌표를 유지하며 입력만큼 적재칸 안에서 걸음 (ClampToCargo)
마차가 돈 만큼만 몸을 함께 돌림 — 시점 회전은 그대로 자유
연출이 끝나면 컴포넌트 복구 + Physics.SyncTransforms + 추락 판정 초기화
```

## 4. 던전 형상을 방 모듈 방식으로 재구성

벽 두께를 줄이면서 벽 생성부를 다시 썼는데, 그 과정에서 **모든 방의 남쪽 벽이 90° 돌아가는 버그**가 생겼다.

```csharp
// 원인 — 길이 방향 벡터의 부호를 무시하고 비교
return along.x > 0.5f ? ... // 남쪽 벽은 길이 방향이 -X 라서 Z축 벽으로 만들어짐
```

남쪽 벽이 제자리에서 사라지고 대신 방 한가운데에 벽판이 서 있었다. 검증 단계 대부분이 순간이동으로 방을 확인하기 때문에, 실제로 걸어서 올라가는 계단·사다리 검사에서만 드러났다.

부호만 고치는 대신 구조를 바꿨다. **방 하나 = 모듈 하나**로 만들고, 면마다 자기 좌표계를 가진 하위 틀을 두어 그 안에서만 계산한다.

```text
모듈 루트 (방)
  Floor_x_y / Ceiling_x_y
  Wall_x_y_방향   ← 이 틀 안에서는 항상 +X = 면 길이 / +Y = 위 / +Z = 바깥
  ClimbFrame      ← +Z = 계단·사다리가 붙는 벽 방향
      Stairs / StairRamp / UpperFloor / UpperLanding / UpperRail
      Ladder  / UpperFloor_Main / SideA / SideB
```

방향 판정 코드(`WallSize` / `PlaneSize` / `BuildCellWalls` / `BuildWall`)를 전부 없앴다. 같은 종류의 축 혼동이 구조적으로 불가능해진다.

계단도 함께 고쳤다. 경사면이 반대쪽 벽까지 그대로 올라가서 플레이어가 캡슐 반지름만큼 앞에서 막히고 층 높이보다 0.3m 낮은 곳에서 멈추고 있었다. 꼭대기에 착지 바닥(`UpperLanding`)을 깔아 앞으로만 걸어도 위층에 올라서게 했다.

## 검증

Play 모드 하네스에 29일차 단계(N)를 추가했고, 28일차 계단·사다리 단계(S)는 **모든** 세로형 방을 걸어서 검사하도록 넓혔다. 기존에는 각각 1개만 검사해서 이번 버그가 두 번째 방에서만 드러나는 것을 놓쳤다.

```text
29일차 신규 단계 N            57 / 0
계단·사다리 단계 S (모듈 전환 후, 문제 시드 고정)   82 / 0
   계단통 20 : 1F → 2F 걸어 올라감 / 내려옴
   계단통 27 : 2F → 3F 걸어 올라감 / 내려옴
   사다리 35 : B1 → 1F / 사다리 47 : B2 → B1
EditMode 배치 테스트          24 / 0
전체 회귀 16단계 (모듈 전환 직전 코드)   S 를 뺀 15단계 0 실패
```

**미완료:** 모듈 방식으로 바꾼 뒤의 전체 회귀 16단계 재실행은 하지 않았다. 모듈 전환은 실내 형상 생성(Runtime)만 건드렸고 배치 규칙(Core)은 손대지 않았지만, 전체 재확인은 다음 일차로 넘긴다.
