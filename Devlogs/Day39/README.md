# 39일차 — 협동 전투·몬스터·함정·장치 동기화 (방장 기준)

## 이번 일차 목표

38일차까지는 같은 물건을 보지만 **몬스터와 함정은 각자 따로** 움직였다. 39일차에는 싸움을 모두가 같은 장면으로 보게 만든다.

```text
방장: 몬스터 AI 실행 → 위치·상태를 초당 10번 방송 → 참가자 화면의 몬스터가 따라 움직임
참가자가 몬스터를 벰 → 방장에게 피해 요청 → 방장이 적용 → 체력·쓰러짐 방송
방장 몬스터가 참가자를 공격 → 방장이 그 참가자에게 피해 전달 → 참가자 체력 감소
```

## 1. 기준 — 경로 해시

- 몬스터·함정·장치는 모두 **씬에 놓인 오브젝트**(훈련장·생성 던전)다. "씬 + 계층 경로(이름#순서)"의 FNV-1a 해시로 같은 오브젝트를 찾는다 (`NetCombatSync.PathHash`).
- 목록(움직이는 몬스터 · 피격 대상 · 함정 · 장치)은 필요할 때만 다시 만든다 (최소 1.5초 간격).
- 혼자 하기에서는 모든 판단이 바로 끝나 기존 동작 그대로다.

## 2. 몬스터

| 항목 | 방장 | 참가자 |
| --- | --- | --- |
| 두뇌·감각·이동 | 실행 | 끔 (`NetCombatSync.PuppetMonsters`) |
| 위치·방향·AI 상태 | 초당 10번 비신뢰 전송 (`MonsterNetState[]`, 24마리씩) | 부드럽게 따라감, 4m 이상 차이나면 즉시 이동 |
| 근접 공격 | 피해 판정 | 휘두르기 연출만 (`PlayNetworkSwing`) |
| 궁수 화살 | 실제 화살 | 피해 0 화살 연출 (`PlayNetworkArrow`) |
| 미믹 | 접근·피격 시 변신 | 방장이 위장을 풀면 변신 연출 (`BeginNetworkReveal`) |
| 웃는 석상 | 규칙 판정 | 위치만 따라감 |

- 웃는 석상은 공통 두뇌가 없어 "움직이는 몬스터" 목록에 따로 넣었다.

## 3. 모든 대원을 대상으로

- `PlayerTargets`: 내 플레이어 + 같은 맵에 있는 다른 원정대원 몸체를 대상 목록으로 준다.
  - `MonsterSensor`: 가장 가까운 **보이는** 대원을 고른다. 시야 판정의 첫 충돌이 그 대원이어야 한다.
  - `MonsterMeleeAttack`: 피격 대상이 다른 원정대원이어도 피해를 준다.
  - `MonsterBrain` · `ChestMimicBehavior`: 공격한 대원을 우선 대상으로 삼는다 (다른 원정대원 포함).
  - `SmilingStatueBehavior`: 가장 가까운 대원을 쫓는다. 내 카메라 **또는 다른 대원 누구라도** 보고 있으면(좌우 50°, 가림 확인) 멈춘다.
- `RemotePlayerTarget`: 다른 대원 몸체에 붙는 피격 대상이다.
  - 같은 맵에 살아 있을 때만 캡슐 충돌을 켠다 (내 몸체는 항상 끔).
  - 방장 화면에서는 1.8m마다 발소리 소음을 낸다 (달리기 추정 시 더 크게).
  - 방장 몬스터(**적 진영**) 공격만 그 대원에게 전달한다 (`PlayerDamageRpc`). 함정(환경 진영)은 전달하지 않는다.

## 4. 피해

- `DamagePipeline.TryApply` 맨 앞에서 `NetCombatSync.TryRelayDamage`가 참가자 규칙을 판단한다.

| 참가자 화면의 피해 | 처리 |
| --- | --- |
| 내 플레이어 | 기존대로 적용 |
| 다른 대원 몸체 | 거부 (방장만 판정) |
| 플레이어 공격 → 몬스터·허수아비·부서지는 벽 | 방장에게 요청(`DamageRequestRpc`). 맞힌 것으로 표시하고 체력은 방장 값을 따른다. |
| 함정·몬스터 → 몬스터 | 거부 (방장 화면의 결과만 사용) |

- 방장은 요청한 대원의 몸체를 공격자로 넣어 적용한다 → 몬스터가 그 대원을 쫓는다.
- `CombatHealth`: 체력이 바뀌면 방송하고(`HealthRpc`), 참가자는 `SetNetworkHealth`로 적용한다 (사망 이벤트 → 쓰러짐·벽 파괴 연출).

## 5. 함정

- `TrapControllerBase.TriggerTrap`을 공통 입구로 바꿨다 (종류별 실제 작동은 `TriggerTrapLocal`).
  - 참가자: 작동 가능 상태면 방장에게 요청하고 직접 작동하지 않는다.
  - 방장: 작동 후 모두에게 방송 → 모두 같은 연출
- **피해는 각자 자기 화면의 함정이 자기 플레이어에게** 준다 (두 번 맞지 않음).

## 6. 장치 — `INetworkDevice`

상태 번호 하나로 맞춘다. 조작한 대원 화면에서 먼저 바뀌고, 방장을 거쳐 나머지 대원에게 적용된다.

| 장치 | 상태 |
| --- | --- |
| 던전 차단기 `DungeonBreaker` | 켜짐 |
| 던전 발전기 `DungeonPowerPlant` | 가동·기동 중 (받으면 같은 기동 연출) |
| 전력 승강기 `DungeonElevator` (버튼이 알림) | 가는·있는 층 (전기가 없으면 바로 맞춤) |
| 배전반 스위치 `DistributionBoardButton` | 메인 전원 · 방 전원 · 철문 열림 |
| 훈련장 발전기 `GeneratorController` | 가동 (연료는 각자 계산) |
| 잠긴 방 문 `LockedRoomDoor` | 열림 |

## 7. 늦게 들어온 대원

참가자가 방장과 같은 맵에 도착하면 `FullStateRequestRpc`를 보낸다. 방장은 **피해 입은 대상의 체력**과 **모든 장치 상태**를 보낸다. 이동 중에는 이전 맵의 몬스터 목표를 비운다.
