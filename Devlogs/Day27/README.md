## 개발 목표

Day26까지 테스트 던전은 매번 똑같은 Terrain 맵 한 장이었다.

Day27에서는 원정마다 구조가 바뀌는 **실내 던전**을 처음 만들었다.
이번 단계는 예쁜 방보다 **어떤 시드에서도 규칙을 지키는 뼈대**를 우선했다.

확정한 규칙:

```text
실내 맵은 던전 씬 지하에 생성하고 지형을 절대 뚫지 않는다
메인 방(시작 방)을 기준으로 모든 방이 끊김 없이 이어진다
실내 서브문 개수 = 외부 서브문 개수 (외부 씬마다 다름, 씬에서 읽음)
실내 서브문 N ↔ 외부 서브문 N 1:1 연결, 서로 겹치지 않는다
외부 문과 실내 문은 순간이동으로 연결한다 (지형 구멍 없음)
같은 날은 같은 구조, 다음 날은 다른 구조
```

# 1. 생성 핵심 — `ProjectI.Generation` 어셈블리

씬 없이 수천 개 시드를 빠르게 검사할 수 있도록
생성 로직을 Unity에 의존하지 않는 순수 C# 전용 어셈블리로 분리했다.

```text
Assets/ProjectI/Scripts/Generation/Core
├─ ProjectI.Generation.asmdef   (noEngineReferences)
├─ DungeonLayout.cs             방·문·서브문 그래프
├─ DungeonGenerationConfig.cs   생성 규칙 값 · DungeonSeed
├─ DungeonLayoutGenerator.cs    생성기
└─ DungeonLayoutValidator.cs    규칙 검증기
```

## 생성 순서 (설계 문서 8.6·8.9·8.12 기준)

```text
1. 시작 방 (0,0) — 남쪽 벽은 정문 자리로 비워 둠
2. 주 경로 — 안쪽(북쪽) 우선으로 겹치지 않게 성장
3. 시작 방 출구 2개 이상 보장
4. 분기 — 주 경로 중간에서 1~3칸씩 성장
5. 순환로 — 깊이 차이가 2 이상인 인접 방을 확률로 연결
6. 막다른 방 20% 이하로 보정
7. 직선 통과 방 일부를 복도로 지정 (연속 최대 3개)
8. 잠긴 문 — 다리(Bridge) 문 하나를 잠그고
   열쇠는 그 문을 지나지 않고 갈 수 있는 방에 배치
9. 서브문 — 외부 서브문 수만큼 배치
10. 회수품·함정·몬스터 후보 표시 (입구 방 제외)
```

## 서브문 배치 규칙

```text
시작 방·최심부·열쇠 방·잠긴 구역·복도 제외
전체 깊이의 앞·중간 구간 우선 (부족하면 전체)
서브문 방끼리 문 경로 2칸 이상
서브문 방끼리·정문 방과 격자상 옆 칸 금지
방 문이 없는 벽에만 배치
조건을 못 맞추면 해당 시도를 버리고 재생성
```

검증 중 두 서브문이 **옆 칸 방에 벽 하나를 사이에 두고 등을 맞댄** 결과가 나와
격자 공간 거리 규칙을 추가했다.

## 시드

```text
시드 = FNV-1a(캠페인 시드, 현재 일차, 던전 씬 이름)
```

`DailySnapshotData`에 `campaignSeed`를 추가했다.
이전 버전 저장 파일은 로드할 때 새 캠페인 시드를 만들고 다음 저장부터 기록한다.

# 2. 외부 문 — 테스트 던전 지상

`02_TestDungeon`에 외부 출입문 3개를 배치했다.

```text
정문      (0, 13)    마차 정면 석조 입구 · 녹색 표시등
서브문 1  (-21, -18) 서남쪽 · 청색 표시등
서브문 2  (21, 6)    동쪽 · 청색 표시등
```

각 문 자리는 Terrain을 평탄화했고,
원래 정문 자리에 있던 왕관 회수품은 (9, -3)으로 옮겼다.

생성기는 이 씬에 배치된 외부 서브문 개수를 읽어 실내 서브문 수를 정한다.
외부 서브문 번호는 0부터 빠짐없이 이어져야 하며,
정문이 1개가 아니거나 번호가 겹치면 생성을 취소한다.

## 지형 관통 방지

```text
외부 씬(생성물 제외)의 가장 낮은 Terrain 바닥·충돌체·렌더러 높이 계산
→ 그보다 12m 아래를 실내 최고 높이 한계로 사용
→ 생성 직후 모든 생성물 최고 높이 재검사
→ 한 곳이라도 넘으면 생성 취소
```

테스트 던전 결과:

```text
외부 최저 -5.0 (경계벽 바닥)
```

# 4. 순간이동 출입문 — `DungeonTeleportDoor`

```text
외부 정문      ↔ 지하 시작 방 정문
외부 서브문 N  ↔ 지하 서브문 N
```

F를 누르면 짧은 암전 후 짝이 되는 문의 도착 지점으로 이동한다.
이동은 `PersistentMapLoader.RequestPlayerTeleport`가 담당하며
이동 중에는 마차 종·저장·중복 순간이동을 막는다.

# 5. 순간이동 즉사 버그

## 증상

던전 정문으로 들어가자마자 플레이어가 사망했다.

## 원인

`PlayerMovement`는 공중 최고 높이를 기억했다가 착지할 때 추락 거리를 계산한다.

지상(약 0)에서 지하(약 -21.4)로 순간이동하면
최고 높이가 지상 값으로 남아 **21m 추락**으로 계산되었다.

```text
(21.4 - 3) × 20 = 368 → 최대 100 → 즉사
```

기존 검증은 위치·지면만 확인하고 체력을 검사하지 않아 놓쳤다.

## 수정

```text
PlayerMovement.NotifyTeleported()
→ 공중 최고점·낙하 속도를 새 위치 기준으로 초기화

PersistentMapLoader
→ 출입문 순간이동 · 마차 순간 배치 · 마차 진입 연출 모두 호출
```

실제 추락 피해는 그대로 동작하는지 함께 확인했다.

## Day 27 결과

원정마다 구조가 바뀌는 지하 실내 던전의 뼈대를 완성했다.

실내는 지형 아래에만 생성되고, 외부 씬의 서브문 개수만큼
서로 떨어진 실내 서브문이 생겨 외부 문과 1:1로 이어진다.

같은 날에는 같은 구조가 유지되어 강제 종료 후에도 같은 던전으로 돌아오며,
생성 규칙은 시드 5,000개 자동 테스트로 매번 검증할 수 있다.

순간이동을 추락으로 계산하던 즉사 버그를 원인부터 수정했고,
추락 피해는 5m 이하 무피해·6m부터 10씩 증가하도록 조정했다.
